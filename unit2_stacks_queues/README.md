I learned how to use and implement stacks and queues as well as when to use each type of data structure. FIFO stands for first in first out and LIFO stands for last in first out. The priority for which item to use first is determined by the order of when each item is inserted into the data structure for both, but the difference is in FIFO the oldest item in the data will be used first while in LIFO the newest item in the data will be used first. FIFO is the ordering for queues, while LIFO is the ordering for stacks.
One challenge I encountered was understanding when to use a stack versus a queue in applications. Understanding FIFO for queues and LIFO for stacks helped to solidify my understanding of when to choose each data structure.
I have worked in restaurants for years and every store I have worked at has followed the FIFO policy when it comes to food products. The importance is that if you did not use the newest product first it would go bad and not be able to be of use. If a stack implementation were to be used in a restaurant then they would have waste due to a rotation issue. If a software tried using a stack to track inventory usage then old product would not be used until after new product has been completely used. A queue would be the perfect implementation for tracking product in a restaurant setting to ensure oldest product is used first. There are scenarios in which a stack is better used implementation such as when items don't have a particular shelf life a good example would be at a brick manufacturer. They would stack bricks on a pallet and the bricks placed first would be on the bottom and the bricks placed last would be on top. The bricks on the top would be used first showing a stack order over a queue.
